# Подписка репетитора на платформу

Три тарифа: **Старт** (бесплатно), **Про** и **Макс**. Тариф определяет лимит
учеников и набор включённых возможностей. Оплата — через ЮKassa, деньги идут
**платформе** (в отличие от оплаты занятий, где магазин оформлен на самого
репетитора, см. [`yookassa.md`](yookassa.md)).

## Тарифы

| Возможность | Старт | Про | Макс |
|---|---|---|---|
| Цена, месяц | 0 ₽ | 1 990 ₽ | 4 900 ₽ |
| Цена, год | — | 19 900 ₽ | 49 000 ₽ |
| Учеников | 3 | 25 | без ограничений |
| Расписание, ДЗ, чат, финансы | ✓ | ✓ | ✓ |
| Банк заданий и тренировка | ✓ | ✓ | ✓ |
| Сборка вариантов ОГЭ/ЕГЭ и PDF | — | ✓ | ✓ |
| ИИ-генерация ДЗ | — | 150 / мес | без ограничений |
| Онлайн-оплата занятий учениками | — | ✓ | ✓ |
| История досок занятий | — | ✓ | ✓ |
| Отчёты родителям об уроке | — | ✓ | ✓ |
| Приоритетная поддержка | — | — | ✓ |

Цены и лимиты лежат в одном месте — `src/plans.js`. Его же импортируют серверные
функции, поэтому клиент и сервер не могут разойтись в цене или лимите.
Год стоит как десять месяцев — это напечатано в интерфейсе, поэтому `year`
обязан оставаться равным `month × 10`.

**«Без ограничений» на «Максе» — с мягким потолком.** В базу уходит не −1, а
`AI_SOFT_CAP` (2000 генераций в месяц, `src/plans.js`): живой репетитор столько
не набирает даже в самый плотный месяц, а вот скрипт или утёкший токен —
запросто, и каждый запрос стоит денег в DeepSeek. Отказ по этому потолку
помечен флагом `soft`, и текст ошибки предлагает написать в поддержку, а не
купить тариф дороже (дороже — некуда).

**ИИ-отчёт родителю — тоже возможность тарифа.** `api/lesson-report.js`
проверяет `parentReports`, то есть на «Старте» он недоступен. До 19.08.2026 там
стояла только проверка авторизации, и ИИ-отчёты работали на любом тарифе.

Пока миграция не выполнена, **ограничения не применяются**: биллинг считается
неустановленным и всё работает как раньше. Это сделано специально — забытая
миграция не должна молча выключить половину платформы.

## Порядок подключения

### 1. Магазин платформы в ЮKassa

Нужен **отдельный** магазин: сюда приходят деньги платформы, а не репетитора.
Пока платформа однопользовательская (репетитор = владелец), допустимо обойтись
одним магазином — тогда переменные `YOOKASSA_PLATFORM_*` можно не задавать, и
подписка будет использовать ключи из `YOOKASSA_SHOP_ID` / `YOOKASSA_SECRET_KEY`.
Как только репетиторов станет больше одного, отдельный магазин обязателен.

### 2. Миграция базы

Выполнить `supabase/subscriptions.sql` в Supabase → SQL Editor. Идемпотентно.

### 3. Переменные окружения Vercel

| Переменная | Значение |
|---|---|
| `YOOKASSA_PLATFORM_SHOP_ID` | магазин платформы (если не задан — берётся магазин репетитора) |
| `YOOKASSA_PLATFORM_SECRET_KEY` | секретный ключ этого магазина |
| `SUPABASE_URL` | то же, что `VITE_SUPABASE_URL` |
| `SUPABASE_SERVICE_ROLE_KEY` | ключ `service_role` |
| `PUBLIC_SITE_URL` | `https://precettore.ru` |

`SUPABASE_SERVICE_ROLE_KEY` нужен и для проверки тарифа: без него сервер не может
узнать, кто пришёл, и `api/generate-hw.js` работает как раньше — анонимно и без
лимитов.

### 4. Адрес для уведомлений

Личный кабинет ЮKassa магазина платформы → Настройки → Уведомления:

```
https://precettore.ru/api/subscription-webhook
```

События: `payment.succeeded` и `payment.canceled`. Если магазин один на всё,
достаточно уже настроенного `/api/yookassa-webhook` — обработчик различает
платежи по `metadata.kind`.

## Как проверить

1. `GET https://precettore.ru/api/subscription` — health-check без создания платежа.
   Ответ: `{"ok":true,"shop":"…","mode":"test|live","dedicated":true|false,"db":true}`.
2. На тестовом магазине оплатить «Про» картой `5555 5555 5555 4477`.
3. Проверить: заказ в истории получил статус `succeeded`, на странице «Подписка»
   тариф стал «Про», а срок — плюс месяц.

## Почему сделано именно так

**Сумму считает сервер.** Клиент присылает только идентификатор тарифа и период;
цена берётся из `src/plans.js` на сервере. Иначе «Макс» покупали бы за рубль.

**Продление — атомарная операция в базе.** RPC `subscription_apply` одним шагом
захватывает флаг `applied` и сдвигает `current_period_end`. ЮKassa повторяет
доставку уведомления сутки, и без этого один платёж продлевал бы подписку
несколько раз.

**Смена тарифа не сжигает остаток.** Оплаченный остаток прибавляется к новому
тарифу: это щедрее пропорционального пересчёта, зато предсказуемо и не требует
объяснять репетитору формулу.

**Ограничения в интерфейсе — подсказки, а не защита.** Клиенту можно подменить
что угодно, поэтому настоящий барьер стоит на сервере и ровно там, где это
имеет цену: ИИ-генерация (расход в DeepSeek) и приём онлайн-оплаты. Лимит
учеников и доступ к сборке вариантов сейчас проверяются только в интерфейсе —
жёстко закрыть их можно будет вместе с включением RLS на `students`/`variants`
(см. `supabase/rls_migration_plan.md`).

**Неудачная генерация не съедает лимит.** Списание идёт до обращения к DeepSeek
(иначе две вкладки проскочат мимо лимита), а при ошибке возвращается обратно
через `usage_refund_ai`.

**Подписка не продлевается сама.** Автоплатёж (сохранённый способ оплаты в
ЮKassa) не делаем: это отдельное согласие плательщика и отдельная ответственность
по 152-ФЗ. Когда срок кончается, доступ становится бесплатным «Стартом», данные
учеников остаются на месте.
