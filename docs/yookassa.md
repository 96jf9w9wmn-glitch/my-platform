# Онлайн-оплата занятий через ЮKassa

Ученик (или родитель) платит из своего кабинета картой либо через СБП, деньги
приходят **напрямую репетитору** — платформа их не держит и не делит. Успешный
платёж сам попадает в историю оплат ученика, как если бы репетитор отметил его
руками.

## Что уже сделано в коде

| Файл | Роль |
|---|---|
| `supabase/yookassa.sql` | таблицы `payment_orders`, `tutor_payment_settings`, RLS и RPC для ученика |
| `api/yookassa.js` | создание платежа: проверяет сессию ученика, **сам считает сумму**, отдаёт ссылку на оплату |
| `api/yookassa-webhook.js` | приём уведомлений: проверяет IP, перепроверяет платёж через API, дописывает его в карточку ученика |
| `src/components/OnlinePayCard.jsx` | кнопка оплаты в кабинете ученика (вкладка «Оплата») |
| `src/components/OnlinePaySettings.jsx` | выключатель и журнал заказов на странице «Финансы» у репетитора |

Пока не выполнена миграция и не заданы ключи, ничего не ломается: у ученика
карточки оплаты просто нет, у репетитора карточка показывает, чего не хватает.

## Порядок подключения

### 1. Магазин в ЮKassa

Зарегистрировать магазин на yookassa.ru (самозанятый или ИП — подойдут оба
режима). После подтверждения в личном кабинете будут доступны **shopId** и
**секретный ключ**. Пока идёт проверка документов, можно работать с тестовым
магазином — ключ у него начинается с `test_`.

### 2. Миграция базы

Выполнить `supabase/yookassa.sql` в Supabase → SQL Editor. Идемпотентно,
повторный запуск безопасен.

### 3. Переменные окружения Vercel

Project → Settings → Environment Variables:

| Переменная | Значение |
|---|---|
| `YOOKASSA_SHOP_ID` | идентификатор магазина |
| `YOOKASSA_SECRET_KEY` | секретный ключ (`test_…` или `live_…`) |
| `SUPABASE_URL` | то же, что `VITE_SUPABASE_URL` |
| `SUPABASE_SERVICE_ROLE_KEY` | ключ `service_role` из Supabase → Settings → API |
| `PUBLIC_SITE_URL` | `https://precettore.ru` |
| `YOOKASSA_RECEIPT` | `1` — только после включения чеков (см. п. 5) |

`SUPABASE_SERVICE_ROLE_KEY` обходит RLS — он нужен вебхуку, чтобы записать
платёж. Держать его только в переменных Vercel, никогда не в `VITE_…` и не в
клиентском коде.

### 4. Адрес для уведомлений

Личный кабинет ЮKassa → Настройки → Уведомления (HTTP-уведомления):

```
https://precettore.ru/api/yookassa-webhook
```

События: `payment.succeeded` и `payment.canceled`.

### 5. Чеки по 54-ФЗ

Самозанятому чек всё равно нужен. Проще всего включить автоотправку:
личный кабинет ЮKassa → «Отправка чеков» → выдать ЮMoney разрешение работать с
чеками, после чего поставить `YOOKASSA_RECEIPT=1`. Тогда чек НПД формируется и
уходит плательщику автоматически.

Пока разрешение не выдано, флаг ставить **нельзя**: платёж с полем `receipt`
будет отклонён. Без флага чек придётся выбивать вручную в «Мой налог».

### 6. Включить приём оплаты

Страница «Финансы» → карточка «Онлайн-оплата» → тумблер. Там же видно, боевой
магазин подключён или тестовый, и лежит журнал последних заказов.

## Как проверить, что всё работает

1. `GET https://precettore.ru/api/yookassa` — health-check без создания платежа.
   Ответ: `{"ok":true,"shop":"…","mode":"test|live","receipts":true|false,"db":true}`.
2. На тестовом магазине оплатить занятие тестовой картой
   `5555 5555 5555 4477`, любой срок в будущем, CVC любой.
3. Проверить, что платёж появился в истории ученика и в журнале заказов, а
   заказ получил статус `succeeded`.

## Почему сделано именно так

**Сумму считает сервер.** Клиент присылает только количество занятий; цена
берётся из `students.lesson_price` карточки ученика у этого репетитора.
Иначе занятие можно было бы оплатить рублём, подменив запрос в браузере.

**Телу уведомления не верим.** Подписи у вебхуков ЮKassa нет, поэтому
подлинность подтверждается двумя независимыми способами: IP отправителя
сверяется со списком сетей ЮKassa, а статус платежа перезапрашивается через
`GET /payments/{id}`.

**Запись идемпотентна.** ЮKassa повторяет доставку сутки, пока не увидит 200,
поэтому перенос платежа в историю ученика защищён атомарным захватом флага
`payment_orders.applied` — одна и та же оплата не может попасть в историю дважды.

**Расхождение сумм не применяется молча.** Если оплаченная сумма не совпала с
суммой заказа, заказ помечается успешным, но в историю ученика не переносится —
такой случай должен разобрать репетитор.
