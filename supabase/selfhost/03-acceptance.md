# Шаг 5. Приёмка после переезда

Переезд считается выполненным, только когда пройдены **все** пункты. Каждый —
это отдельный слой Supabase; провал любого означает, что часть приложения молча
не работает. Проверять на реальном сайте после переключения переменных, а не
на локальной сборке.

Отметки ставить честно: непроверенный пункт — это не «наверное работает».

---

## A. Данные доехали

- [ ] Числа строк из `restore-selfhost.sh` совпадают со старой базой по всем
      таблицам: `students`, `homework`, `chat_messages`, `student_accounts`,
      `variants`, `variant_submissions`, `notifications`, `tasks`, `boards`,
      `board_snapshots`, `lesson_reports`, `tutor_expenses`.

Ломаются молча: клиент получает ошибку, а UI часто показывает просто пустоту.

- [ ] `student_login` — вход ученика по телефону и паролю.
- [ ] `student_validate_session` — перезагрузить страницу ученика, сессия жива.
- [ ] `student_register` — регистрация нового ученика.
- [ ] `student_reset_password` — сброс пароля ученика.
- [ ] `invite_claim` — вход по ссылке-приглашению.
- [ ] `homework_open` — открытие ДЗ с таймером (время ставит сервер один раз).
- [ ] `task_attempt_log` — решить задание, попытка записалась.
- [ ] `board_snapshot_save` / `_list` / `_get` — закрыть доску, снимок появился.
- [ ] `lesson_report_list_parent` — вход родителя по коду, отчёты видны.
